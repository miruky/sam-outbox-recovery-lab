# 権限の範囲

テンプレートでは各関数に専用の実行ロールを定義し、必要なテーブル、キュー、イベントバス、ロググループをARNで指定します。各インラインポリシーを確認してから、利用するAWS環境へデプロイしてください。

| 主体 | 主な操作 |
|:--|:--|
| 注文関数 | 注文とアウトボックスの保存、受付状態の更新、現在の集計の参照 |
| 中継関数 | 対象Streamの取得、アウトボックス更新、対象バスへのPutEvents |
| 集計・再構築関数 | 自分のSQSキューの取得と削除、世代の条件確認、集計と処理済みIDの保存 |
| 通知関数 | 自分のSQSキューの取得と削除、模擬通知と処理済みIDの保存 |
| 制御関数 | 制御テーブルの更新、照合対象の参照、指定アーカイブからの再生 |
| 状態機械 | 制御関数のInvokeFunction |

EventBridgeからSQSへのキューポリシーではSourceArnを対象ルールへ、SourceAccountをデプロイ先へ限定します。Step Functionsの信頼ポリシーも対象状態機械とアカウントへ限定します。Lambdaの信頼ポリシーはLambdaサービスを主体にします。

`dynamodb:ListStreams` は対象リソースARNを指定できないため `Resource: "*"` です。実行時に生成する再生名のDescribeReplay、StartReplay、CancelReplayは `replay/miruky-*` に限定します。このサンプルを複数同居させる場合は、再生権限の名前範囲が共通になる点を評価してください。

CLIのデプロイ主体にはテンプレート内サービスの作成・参照・削除と、対象IAMロールの管理、サービスへ渡すPassRoleが必要です。既存の認証を使い、サンプルから認証キーの作成や管理者ポリシーの付与は行いません。

操作補助はAWS CLIで制御関数を呼び出し、状態機械を開始し、対象キューとアウトボックスを参照します。HTTP APIはAWS CLIから取得した短期認証を使ってSigV4署名し、`execute-api:Invoke` で許可された主体だけが呼び出せます。署名用認証値はファイルにも端末にも出しません。
